# Dead Fire Phase 1 (Foundation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the empty `comp4900sef` UE 4.27 project into a playable foundation: drive a Sedan around a looped test track, exit on foot as the mannequin, shoot, and re-enter, with the race GameMode/State skeleton underneath.

**Architecture:** One C++ game module (`comp4900sef`) holds all gameplay classes (prefix `DF`); Blueprint children under `/Game/DeadFire/Blueprints/` carry assets and tunables. Levels, Blueprints and smoke tests are produced by Python scripts run inside the editor through the `unreal-mcp-ue4` MCP server. Editor automation tests in the module cover the pure logic (damage routing, enter/exit state, spline generation).

**Tech Stack:** UE 4.27.2 (D:\UE_4.27), PhysXVehicles, classic input, UnrealBuildTool with MSVC v142, editor Python 3.7 via MCP, UE Automation framework.

**Spec:** `docs/superpowers/specs/2026-10-20-dead-fire-design.md`

## Global Constraints

- Engine: Unreal Engine 4.27.2 at `D:\UE_4.27`; project `comp4900sef/comp4900sef.uproject`; module name `comp4900sef` (matches the existing `ActiveGameNameRedirects`).
- Class prefix `DF`; Blueprint children in `/Game/DeadFire/Blueprints/`; maps in `/Game/DeadFire/Maps/`.
- Free content only: engine template packs copied with their original package paths (`/Game/Vehicle`, `/Game/Mannequin`, `/Game/Geometry`, `/Game/VehicleAdv`).
- Spec §4 values: vehicle body health 100; tire health 30; blown-tire speed scale 0.8; exit allowed below 10 km/h; character health 100; race time 120 s; checkpoint bonus +8 s; +100 per lap; +50 per kill; max deaths 3.
- Every tunable is `UPROPERTY(EditAnywhere, BlueprintReadWrite)` under a `Dead Fire|...` category; every gameplay hook is a `BlueprintImplementableEvent` or `BlueprintAssignable` delegate.
- Enter/exit must work without a controller (editor automation runs with no PlayerController).
- Do not commit; the user asked for commits only on request. Leave the working tree ready and list the commit command in the final report.

## Review Focus

1. Exiting the car next to a barrier: the character must not be placed inside the barrier. Expected: `FindExitLocation` tries left, right, then behind, and `ExitVehicle` returns false if no spot is free. (Test added in Task 4.)
2. Pressing Interact while the car is still rolling: expected no exit and no state change. (Test in Task 4.)
3. A point-damage hit whose bone name is not a wheel but whose impact is within 60 cm of a wheel: expected routed to that tire (proximity fallback). (Test in Task 2.)
4. Damage applied after the vehicle is already destroyed: expected ignored, no second `OnVehicleDestroyed`. (Test in Task 2.)
5. A track spline with fewer than 2 points: expected no meshes generated and no crash on construction. (Test in Task 5.)
