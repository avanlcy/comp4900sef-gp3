# Dead Fire (死火) — COMP 4900SEF Group 3

An action-racing hybrid built in **Unreal Engine 4.27.2**: race laps on a looped track, blow up rival cars, and get out of the car on foot to find items and shortcuts. See the proposal for the pitch, `docs/superpowers/specs/2026-10-20-dead-fire-design.md` for the design and phase plan, and `docs/superpowers/specs/2026-10-21-phase2-race-flow-design.md` for the race rules.

## Current state: Phase 2 (race flow)

- Drive a Sedan around `L_TestTrack` (W/S/A/D, Space handbrake, Tab in-car camera).
- Stop and press **E** to get out as the mannequin; walk/run/jump, mouse look, **left mouse** fires a hitscan weapon. Press **E** next to the car to get back in.
- Four checkpoint gates on the loop, index 0 on the start line. Only the next gate counts (driving backwards or skipping gates credits nothing); each gate adds **+8 s** to the 120 s clock, and crossing the start line completes a lap (**+100**).
- Three lives. A wrecked car (driven or parked) or a killed character costs a life; 2 s later the player is back in a car at the last gate (a fresh one if theirs was wrecked) with the character revived and inside. The third death ends the race (game over).
- Off-track timer: driving more than 5 m beyond the edge of every road for 5 s puts the car back at the last gate without costing a life. On foot the timer never runs.
- Race end (clock at 0 or no lives left): input stops and a summary shows the outcome (`RACE COMPLETE` at 300 points or more, `TIME UP`, `GAME OVER`), place, score, laps, kills and deaths, with **Retry** and **Quit**.
- UMG HUD: score, laps, kills, lives, clock, speed and gear, car or character health and tires, crosshair on foot, enter/exit prompts, and warnings (`RETURN TO TRACK` countdown, `WRECKED`, `YOU DIED`, `CHECKPOINT  +8 s`).

Phases 3–6 (items and damage, AI racers, menus, shipping) are described in the design document.

The project is a **C++ project**: the editor needs the compiled game module before it can open. The first open compiles it automatically (click **Yes** when asked to rebuild `comp4900sef`), or build from the command line as below.

## Build and run

```powershell
# One-off: generate Visual Studio project files (optional, for IDE work)
# Right-click comp4900sef\comp4900sef.uproject -> Generate Visual Studio project files

# Build the editor module
D:\UE_4.27\Engine\Build\BatchFiles\Build.bat comp4900sefEditor Win64 Development -Project="<repo>\comp4900sef\comp4900sef.uproject" -WaitMutex

# Open the editor
D:\UE_4.27\Engine\Binaries\Win64\UE4Editor.exe "<repo>\comp4900sef\comp4900sef.uproject"
```

Replace `D:\UE_4.27` with your engine path. The editor opens `L_TestTrack`; press **Play**.

The Starter Content pack is git-ignored and re-added automatically on first open. The committed free content comes from the engine's template packs (`Content/Vehicle`, `Content/Mannequin`, `Content/Geometry`, `Content/VehicleAdv`).

## Tests

```powershell
.\tools\run_tests.ps1                     # all DeadFire.* automation tests, headless
.\tools\run_tests.ps1 -Filter DeadFire.Vehicle
```

Inside the editor: **Window → Developer Tools → Session Frontend → Automation**, or the console command `Automation RunTests DeadFire`. Two tests run a real Play-In-Editor session on `L_TestTrack` and save screenshots to `comp4900sef/Saved/Screenshots/Windows/` (black when run headless):

- `DeadFire.PIE.DriveExitFireEnter` drives with the real key bindings, exits, shoots the car, and re-enters.
- `DeadFire.PIE.CheckpointWreckRespawnSummary` drives through gate 1 (clock +8 s), wrecks the car (one life, a fresh car at gate 1 with the character inside), leaves the road (put back at gate 1, no life lost), and runs the clock out (summary on screen, input off).

## Editor automation (optional)

The Blueprints and the test level were generated by the Python scripts in `comp4900sef/Script/`. Run them in this order from the editor's Python console, replacing `<repo>` with your clone's path:

```python
exec(open(r'<repo>/comp4900sef/Script/df_create_blueprints.py').read())   # BP_DF* children, BP_DFCheckpoint included
exec(open(r'<repo>/comp4900sef/Script/df_build_test_track.py').read())    # empties and rebuilds L_TestTrack with its four gates
```

Python remote execution is enabled and pinned to loopback (`RemoteExecutionMulticastBindAddress=127.0.0.1` in `Config/DefaultEngine.ini`). To drive the running editor from outside:

```powershell
python tools\ue_remote.py --code "import unreal; print(unreal.EditorLevelLibrary.get_editor_world().get_name())"
python tools\ue_remote.py --code "exec(open(r'<repo>/comp4900sef/Script/df_build_test_track.py').read())"
python tools\ue_remote.py --file comp4900sef\Script\df_resave_test_track.py
python tools\ue_remote.py --console "Automation RunTests DeadFire"
```

`--file` sends the script text and gets it echoed back, which overflows the client's reply buffer for the two larger scripts; run those with `--code "exec(...)"` as above.

If you use the `unreal-mcp-ue4` MCP server, set `UNREAL_MCP_BIND_ADDRESS=127.0.0.1` in its environment so it talks on the same loopback address.

### Extending in Blueprint

Every tunable is exposed under a **Dead Fire** category on the `BP_DF*` assets (health, tire health, exit speed, weapon damage, race time, points per lap/kill...). The race rules are under **Dead Fire|Race** on `BP_DFRaceGameMode`: `MaxDeaths` (3), `RespawnDelay` (2 s), `OffTrackMargin` (500 cm beyond the road edge), `OffTrackGraceSeconds` (5 s), next to `RaceTimeLimit`, `CheckpointTimeBonus` and `ScoreRequirement`. Gates are tuned under **Dead Fire|Checkpoint** (`TriggerHalfExtent`, `PoleOffset`, `PoleScale`, `RespawnHeightOffset` on `BP_DFCheckpoint`; `CheckpointIndex` on each placed gate, 0 for the start line).

Gameplay hooks are Blueprint events on the C++ classes: `OnVehicleDamaged`, `OnTireBlown`, `OnVehicleDestroyed`, `OnOccupantEntered/Exited`, `OnCharacterDamaged/Died/Revived`, `OnEnteredVehicle/ExitedVehicle`, `OnRaceEnded`, `OnRacerRespawned`, and the `OnFired` / `OnDestroyedDelegate` delegates. Add visuals, sounds and extra logic in the Blueprint children; only change C++ when a new system is needed.

### Restyling the HUD

The HUD and the summary are C++ widgets (`DFRaceHUDWidget`, `DFRaceSummaryWidget`) that build a plain layout when they have no designer tree. To restyle one, create a Widget Blueprint whose parent class is that widget, lay it out in the designer, and name each element like its C++ property. The C++ keeps filling them in, and any element you leave out is skipped. Then set the Widget Blueprint as `HUDWidgetClass` or `SummaryWidgetClass` on `BP_DFHUD`.

- HUD: `ScoreText`, `LapText`, `KillsText`, `LivesText`, `TimeText`, `SpeedText`, `GearText`, `VehicleHealthText`, `VehicleHealthBar`, `TireText`, `CharacterHealthText`, `CharacterHealthBar`, `CrosshairText`, `PromptText`, `WarningText`, and the containers `VehiclePanel` / `CharacterPanel`. Car-only elements are hidden on foot and foot-only ones in the car.
- Summary: `TitleText`, `PlaceText`, `StatsText`, `RetryButton`, `QuitButton`, `RetryLabel`, `QuitLabel`.
