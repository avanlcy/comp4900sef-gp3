# Dead Fire (死火) — COMP 4900SEF Group 3

An action-racing hybrid built in **Unreal Engine 4.27.2**: race laps on a looped track, blow up rival cars, and get out of the car on foot to find items and shortcuts. See the proposal for the pitch and `docs/superpowers/specs/2026-10-20-dead-fire-design.md` for the design and phase plan.

## Current state: Phase 1 (foundation)

- Drive a Sedan around `L_TestTrack` (W/S/A/D, Space handbrake, Tab in-car camera).
- Stop and press **E** to get out as the mannequin; walk/run/jump, mouse look, **left mouse** fires a hitscan weapon.
- Press **E** next to the car to get back in.
- Canvas HUD with score, clock, speed, gear, car health, tire health, prompts.
- Race framework skeleton: GameMode with the clock and scoring hooks, per-racer score component, track spline tool.

Phases 2–6 (checkpoints and race flow, items and damage, AI racers, menus, shipping) are described in the design document.

## Prerequisites

| Tool | Version |
|---|---|
| Unreal Engine | 4.27.2 (Epic Games Launcher) |
| Visual Studio | 2019 (16.11) or 2022 with the **Desktop development with C++** workload. UE 4.27 prefers the MSVC v142 (2019) toolset; on VS 2022 install the "MSVC v142 - VS 2019 C++ x64/x86 build tools" component. |
| Windows SDK | 10.0.19041 or newer |

The project is a **C++ project**: the editor needs the compiled game module before it can open. The first open compiles it automatically (click **Yes** when asked to rebuild `comp4900sef`), or build from the command line as below.

## Build and run

```powershell
# One-off: generate Visual Studio project files (optional, for IDE work)
# Right-click comp4900sef\comp4900sef.uproject -> Generate Visual Studio project files

# Build the editor module
D:\UE_4.27\Engine\Build\BatchFiles\Build.bat comp4900sefEditor Win64 Development -Project="<repo>\comp4900sef\comp4900sef.uproject" -WaitMutex

# Open the editor
D:\UE_4.27\Engine\Binaries\Win64\UE4Editor.exe "<repo>\comp4900sef\comp4900sef.uproject"
```

Replace `D:\UE_4.27` with your engine path. The editor opens `L_TestTrack`; press **Play**.

The Starter Content pack is git-ignored and re-added automatically on first open. The committed free content comes from the engine's template packs (`Content/Vehicle`, `Content/Mannequin`, `Content/Geometry`, `Content/VehicleAdv`).

## Tests

```powershell
.\tools\run_tests.ps1                     # all DeadFire.* automation tests, headless
.\tools\run_tests.ps1 -Filter DeadFire.Vehicle
```

Inside the editor: **Window → Developer Tools → Session Frontend → Automation**, or the console command `Automation RunTests DeadFire`. The `DeadFire.PIE.DriveExitFireEnter` test starts Play-In-Editor, drives with the real key bindings, exits, shoots, re-enters, and saves screenshots to `comp4900sef/Saved/Screenshots/Windows/`.

## Editor automation (optional)

The Blueprints and the test level were generated by the Python scripts in `comp4900sef/Script/` (run them from the editor's Python console or the Output Log with `py <path>`; `df_build_test_track.py` recreates `L_TestTrack` from scratch). Python remote execution is enabled and pinned to loopback (`RemoteExecutionMulticastBindAddress=127.0.0.1` in `Config/DefaultEngine.ini`). To drive the running editor from outside:

```powershell
python tools\ue_remote.py --code "import unreal; print(unreal.EditorLevelLibrary.get_editor_world().get_name())"
python tools\ue_remote.py --file comp4900sef\Script\df_resave_test_track.py
python tools\ue_remote.py --console "Automation RunTests DeadFire"
```

If you use the `unreal-mcp-ue4` MCP server, set `UNREAL_MCP_BIND_ADDRESS=127.0.0.1` in its environment so it talks on the same loopback address.

### Extending in Blueprint

Every tunable is exposed under a **Dead Fire** category on the `BP_DF*` assets (health, tire health, exit speed, weapon damage, race time, points per lap/kill...). Gameplay hooks are Blueprint events on the C++ classes: `OnVehicleDamaged`, `OnTireBlown`, `OnVehicleDestroyed`, `OnOccupantEntered/Exited`, `OnCharacterDamaged/Died`, `OnEnteredVehicle/ExitedVehicle`, `OnRaceEnded`, and the `OnFired` / `OnDestroyedDelegate` delegates. Add visuals, sounds and extra logic in the Blueprint children; only change C++ when a new system is needed.
